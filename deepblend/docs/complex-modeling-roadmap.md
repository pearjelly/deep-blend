# DeepBlend 后续计划：少量操作完成复杂建模

更新：2026-10-11。承接用户最新目标。0.4.0 摄影复用已正式发布并完成公开安装读回；下一项产品实施以本计划的建模任务为优先，替代原先优先动画/导出的排序。

## 目标与现有基础

用户描述想做的模型，给出少量尺寸和外观要求，得到结构清楚、可继续修改的实际 Blender 模型，并能检查和交付。先把支持范围内的任务做扎实，再根据真实成功和失败扩展范围。

已有旋转截面、曲线路径、壁厚、布尔、镜像/阵列、倒角、版本化配方、局部补丁、真实网格检查和多视角评审。过去记录仍有连接部位观感与实际模型评审的未完成项。现有多部件音箱配方有空腔、格栅、旋钮、散热口与接线，但公开参数仅覆盖外壳颜色、粗糙度和曝光。复杂结构已经能表达，用户修改尺寸与装配仍需更底层的编辑。

本轮只读能力核对已确认：音箱、灯具、玻璃陶瓷三份配方及场景与公开 0.3.9 的字节一致，分别含 111、24、6 个实体，均没有结构类公开参数。当前配方 Schema 仅支持材质和曝光绑定；在内存中尝试增加生成器尺寸参数被公开校验器明确拒绝。这是接口能力基线，尚不是完成任务的操作/耗时基线。首项改进因此需要补齐受约束的几何与装配参数机制，再验证少量输入能真正改变复杂结构；只增加外观参数不足以满足本目标。

依据：现有 product-roadmap.md、improvement-plan.md、modeling.md、quality-benchmarks.md、modular-speaker/recipe.json。历史简化消融不能当作旧版本质量；配方自测不能当作任意自然语言任务成功。

## 实施顺序

| 阶段 | 用户能完成的事 | 交付与验收 |
| --- | --- | --- |
| 1：复杂模型的简单入口 | 选择一个多部件产品任务，用 3–6 项必要输入调整结构并创建 | 先测已发布版本完成音箱尺寸/结构改造所需操作、等待与返工。选择最影响任务的一处瓶颈，再实现有完整约束的入口；修改外壳尺寸时内部、格栅和装配位置正确联动，材料及未修改细节保留 |
| 2：质量可见且可修 | 看到具体几何/装配问题，并明确执行相应修整 | 从实际失败挑选厚度、开口、倒角、接缝或细节密度中的一项；保存与独立重开后检查尺寸、连通/闭合、相交、法线和面数预算；前后图固定相机、灯光和渲染预算 |
| 3：一句任务到实际模型 | 用自然语言描述受支持任务，确认少量重要输入，创建后继续定向修改 | 在隔离 DSH 环境验证真实 DeepSeek Agent/工具调用，保存任务、澄清、调用、实际模型和失败记录。脚本化模拟与固定模板各自标明，不计为真实模型自主建模 |
| 4：可交付的成品 | 检查多视角与局部细节，交付可编辑 .blend、图片及需要的动画 | 以音箱/厚壁器皿/曲面灯具扩展任务矩阵。核对成品源版本、模型组织和文件重开；教程从干净公开安装实做至交付。动画/摄影服务于模型任务 |

第一阶段先选音箱任务建立实际操作基线。不会同时承诺任意风格、任意几何或制造认证；碰到表达能力不足时增加有真实任务支持的能力，不靠更多表单掩盖问题。

## 第一轮两周工作目标

第 1–3 天：完成首个复杂模型修改基线，交付一个减少实际操作且保持装配正确的独立切片；建立默认、两组正常尺寸与明确无效组合的真实模型验证。

第 4–6 天：处理最明显的几何或细节短板，让检查结果能引导一次有效修整；补主图、侧/背面、灰模和问题部位近景的固定对照。

第 7–10 天：验证真实自然语言建模与继续修改。先覆盖已支持任务，再测试有实际结构变化的请求；记录需要人工澄清和仍失败的情况，并据此改进 Agent 使用说明与工具反馈。

第 11–14 天：扩展第二类模型，完成安装到交付的教程与升级保留测试，按真实反馈重新排序。日期是实施目标，每天先接续未完成候选；较大能力跨日开发，每日稳定版本须有独立用户收益。

## 判断是否接近目标

- 简单：记录用户提供的输入数、点击/交互数、需手改 JSON 或 Blender 的次数、确认与返工次数；同一任务与已发布版本比较。首个结构入口目标是必要输入不超过六项，一次明确创建得到可编辑结果。
- 复杂：任务明确包含多部件装配、尺寸联动和真实细节，不能把改变颜色或提高采样记为复杂建模进展。
- 正确：在声明范围内核对实际尺寸、部件关系、适用的闭合/连通、相交、法线、预算和保存重建一致；失败保留原版本并给出具体可修原因。
- 高质量：固定条件实图分别判断轮廓、局部接缝、材质和目标吻合。技术检查通过不等于成品观感通过；未发生的外部审阅和用户采用标记未测。
- 省事与可靠：记录总耗时、模型调用成本、首次完成、取消/恢复和历史保护。先得到基线再设改善比例，不能用自动化脚本耗时冒充真人节省。

## 当前尺寸联动候选（尚未发布）

首个实际任务采用 111 部件音箱。0.4.0 的对象尺寸入口只修改外壳：从 264 改成 300 mm 后，深度和高度也随比例变化，内腔及装配件未联动。该基线没有完成目标任务。

候选增加盒体局部三轴尺寸、受约束的配方尺寸与位置映射，以及显式动画位置平移。三个毫米输入分别控制箱体宽 264–340、深 138–180、高 162–220；当前支持扩展尺寸，缩小超出声明范围会被拒绝。外壳、内腔、前后开口和盖板联动，格栅及控制件保留自身尺寸并移动到对应装配位置，箱底高度保持不变。主图和背面摄影机随尺寸调整距离及瞄准点，细节摄影机跟随对应部件。

真实 Blender 已核对默认部件几何与原版一致，修改后的实际尺寸、外壳与内腔的边界差、按钮行程及保存文件重开。固定低采样渲染用于发现和修正边界尺寸的裁切问题；它不能替代发布成品的画质验收，也不证明最小壁厚或制造适用性。

候选已接入随包图库，并保留原版 1.0.0 的锁定输入。真实 DSH 浏览器创建、独立保存文件重开、边界尺寸和细节构图已验证；完整工作台操作还覆盖部件编辑、材质修改、历史保护、恢复及并发冲突。进入发布前仍需完整验收、最新提交的 Linux CI 和准确来源的干净构建。真实 DeepSeek 会话已提交任务，但返回密钥无效，未进入建模工具调用；自然语言任务成功率和外部用户采用情况尚未测量。

本次尺寸入口用于创建新模型。下一轮直接解决已有音箱的整套尺寸修改：从当前版本修改三项尺寸并保存，保留用户已改的材质、修饰器和摄影设置，不重新创建项目替代修改任务。尺寸状态需要随版本恢复；手动修改与联动参数冲突时给出明确处理入口。验收沿用实际 0.4.0 修改任务，核对输入与操作次数、原始版本保护及重新打开后的装配关系。候选稳定后按新增能力发布 minor 版本，继续完整执行 GitHub、七包 npm 和社区流程。
