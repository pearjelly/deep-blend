# 有界实体源码读取：实测与候选

2026-10-15，正式 deepblend 预设的真实 bai 宝塔任务在读取已有叶片控制网格时，
`read` 返回未知工具；完整场景输出溢出后，模型只能反复 grep 多行坐标。
第一次只读阶段 27 次工具调用、1,020,984 ms，没有保存修改；第二次继续只读搜索后
由维护者暂停。原始会话和失败保留在隔离任务目录，未作为建模成功计数。

写入前的工具平面探针：`sourceEntityId` 尚未声明；传入该字段仍调用
`getScene({full:false})`，返回成功却没有源码。探针保存在 `.tmp-source-chunks/before.json`。

候选扩展已有 `blender_scene_get`，只读取指定保存版本的单个实体，返回紧凑 JSON
片段、显式字符偏移、下一偏移和实体文本 SHA-256。它不开放文件路径、脚本或写工具，
也不把几何合法性当作成品观感验收。非首片必须指定返回的 revision；逐片核对实体哈希，
串接文本后再解析 JSON。普通摘要和 full 读取保持兼容。

本地验收：136/136 单元与契约文件通过（2038 项自计断言与1776个 node:test
用例）；工具输出专项184/184，真实 Host/Blender 工具平面54/54。后者在后续编辑
已保存的项目中完整读取旧实体，逐字对照实际保存的 JSON，并确认旧文件与当前指针不变。
真实 bai 界面工具调用10/10通过，视觉闭环13/13通过（本次未触发可选的交接检查）。
测试首次使用了不存在的私有 desktop profile，
视觉入口在读取配置时失败，原始日志保留；改用已存在的私有 headless 配置继续验收，
没有更改个人部署。

一致。独立只读检查逐字匹配保存实体，257个受保护旧文件校验和不变。这证明实际
