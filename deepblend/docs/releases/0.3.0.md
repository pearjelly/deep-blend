# DeepBlend Studio 0.3.0 — create, refine and render product scenes in DSH

This release brings the October 3–6 creation workflow into the published npm packages and
prebuilt bundle. Start with an editable product recipe or import your own model, adjust the
scene in the workbench, compare real Blender renders, and deliver PNG frames and an MP4.

## Try it with a cup

The [illustrated cup walkthrough](https://github.com/pearjelly/deep-blend/blob/v0.3.0/deepblend/docs/creator-tutorial.md)
creates four saved revisions: change the height, glaze roughness and key light, then deliver a
single frame. The images are original Blender outputs; visible handle-root bulges are documented.

![Original cup tutorial output](https://raw.githubusercontent.com/pearjelly/deep-blend/v0.3.0/deepblend/docs/assets/creator-tutorial/cup-final-frame.png)

## What you can do

- Start from lamp, glass-and-ceramic, speaker and handled-cup recipes. Edit dimensions,
  profiles, bevels, arrays, local materials and procedural surface grain.
- Upload and preview models, textures and environment maps. Browser file or directory
  selection keeps glTF/GLB/OBJ dependencies and relative paths together.
- Edit camera focal length, position and target; change lights and add an area fill light.
- Compare immutable scene revisions and fixed-view beauty/clay inspections. Keep reference
  images, design goals and preview source records with the project.
- Use the public JavaScript/TypeScript authoring SDK and versioned schemas to validate,
  compile and extend scene recipes.

## More reliable iteration and delivery

Render profile selections now reach the renderer. Default resume keeps the original sampling
configuration; completed frames continue straight to encoding. Cancellation retains active
work until process exit is confirmed. Per-frame provenance identifies mixed settings and
unknown legacy sources. Numeric fields preserve empty drafts, and language changes retain edits.

Model imports preserve materials, textures and color/data roles. Image budgets are checked
before native decoding. Late file selections are rejected after project/revision changes,
and durable upload receipts can recover lost completion or cancellation responses.

## Install or update

For an existing npm installation, remove the previous bundle registration before adding 0.3.0:

```sh
dsh plugin --profile web remove @deepblend/dsh-blender-bundle
```

Then install the release:

```sh
dsh plugin --profile web add @deepblend/dsh-blender-bundle@0.3.0
```

Or use the prebuilt bundle:

```sh
dsh plugin --profile web add https://github.com/pearjelly/deep-blend/releases/download/v0.3.0/deepblend-bundle.tgz
```

Restart `dsh web`, select **DeepBlend Studio** in a new session, and open the Blender workbench.
Requires DSH **0.1.5-rc.2** on Node.js **22.23.3 or newer**, Blender **5.2.1**, and FFmpeg/ffprobe for MP4 delivery.
See the [installation guide](https://github.com/pearjelly/deep-blend/blob/v0.3.0/deepblend/docs/install.md).
The seven packages share version 0.3.0.

## Validation and scope

Product acceptance, browser/native results and their exact source trees are recorded in the
[acceptance register](https://github.com/pearjelly/deep-blend/blob/v0.3.0/deepblend/docs/milestone-status.md).
Release installation and package checks are verified separately before publication.

Independent user creation, external author reuse and public interface adoption remain open.
Functional delivery does not establish artistic quality. The cup tutorial delivers a still image
and a single-frame MP4; the recipe does not create turntable animation automatically.
