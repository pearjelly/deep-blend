# DeepBlend 0.6.0 — 继续调整已有整套模型

已有音箱项目可在场景树直接修改宽、深、高，一次保存生成同一项目的新版本和真实
预览。外壳、内腔、开口与部件装配位置联动，保留独立修改的材质、倒角、修饰器、
摄影设置及原始版本。恢复历史会恢复该版本的整体尺寸。

发布维护同时修复 npm 预演：`--dry-run` 验证全部七包，明确报告未发布，不再把
缺少公开版本误判为失败。真实发布仍保留公开 registry 读回。

智能体新增 `blender_recipe_parameters`，先读参数和版本，再条件保存。
保存来源和参数状态在同一事务发布；相同请求重试不会重复创建版本。
过期版本、无效参数、被修改的受控几何或损坏来源会拒绝保存，并保留当前项目。
作者 SDK 支持读取保存来源和生成受约束的普通场景补丁。

新功能通过真实 DSH/浏览器/Blender 专项检查 24/24，同一源码的 Linux 原始报告也为
24/24。摄影回归 36/36，仓库外打包 SDK 消费者通过严格类型与实际 JavaScript 检查。
打包安装包的七模块、18 个工具、图片处理、已有装配保存与重试及环境自检通过。
最终完整验收和公开发布状态以 GitHub Release 附件与每日发布记录为准。
原版没有几何绑定的配方仍通过部件编辑继续修改。

用法见[音箱尺寸说明](../sized-speaker.md)。真实 DeepSeek Agent 凭据仍待恢复，
脚本化工具调用与原生验证不计为自然语言任务成功或外部用户采用。

## 安装读回发现的问题（2026-10-12）

0.6.0 的 GitHub Release 和七个 npm 包已公开。整轮公开三路安装验证中，
自包含 tarball 路径部署了旧工作区的预设，未通过字节一致性检查。安装包
内部的新预设正确，但 DSH 从配置目录解析独立插件名，回退到了机器上的
旧工作区。此版本不能记作三路发布验收完成；0.6.1 将修复组件归属并重新
验证。原版本和失败证据保留，npm 版本不会覆盖。
