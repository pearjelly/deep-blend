# 0.18.0：光台工作台

工作台围绕「开始 → 看结果 → 调整 → 导出」组织创作。本页介绍功能，并保留 2026-10-22 首次安装复测及修复时的记录；最终来源的完整验收、安装与公开渠道结果见 [GitHub Release](https://github.com/pearjelly/deep-blend/releases/tag/v0.18.0) 的证据资产。

## 围绕结果继续创作

工作台按「开始 → 看结果 → 调整 → 导出」组织操作。从配方或基础项目开始后，可以在大图旁查看图片来源版本，再打开尺寸、材质、摄影或素材工具继续调整。已有作品可从顶部切换，最近保存的结果以缩略图排列，便于回看。

打开历史结果时，界面标明它与当前版本的区别，并提供「与当前版本比较」和前往版本页保存可编辑副本的入口。没有预览的版本会明确显示尚无图片，工程仍可从版本页访问。这里沿用已有的渲染、版本和副本功能，具体交付范围见[保存可编辑副本](../usage.md#editable-snapshot)。

## 操作更容易找到

「创作提示」按任务展开对象列表、材质与灯光、素材或独立检查工具。查看历史图片时，选择灰模或细节检查会回到当前版本的检查面板；选择场景中的相机或灯光，会展开对应编辑器。打开这些入口本身不会提交编辑或启动渲染。

图片解码前预留显示空间，减少加载时的版面跳动。创建基础项目而未请求预览时，成功提示仍然可见。窄屏布局、浅色与深色外观、键盘焦点也随新工作台调整。

## 软件验收范围

此前冻结提交 `c8d1e2e5e04b8a4e96367e00e3c3369a4b25be19` 完成一次未修改入口的 43 套完整原生验收，进程正常退出，运行前后 956 个跟踪文件的内容保持一致。对应的五项 CI 全部通过；CI 使用的合并预览提交与该冻结提交的源码树一致。具体提交、时间、运行环境和原始记录摘要见[历史验收记录](../validation/release-0.18.0.json)，该记录保留原样，仅适用于上述来源。

验收覆盖真实 Blender 编译、渲染与恢复、智能体工具、资源上传、摄影和尺寸编辑、版本历史及浏览器下载。针对新界面的七处行为修复，变异检查均能检出错误。桌面和窄屏截图重新采自当前界面，截图本身不充当原生渲染验收。

后续发布候选压缩包的首次安装验收未通过：受管 Blender 在安装目录新增了 25 个 Python 字节码缓存，七包原有文件均保持不变。新候选在导入本地模块前明确禁止写入字节码，并保留原有环境隔离。该轮浏览器辅助脚本另有等待图片区域错误，已单独纠正，产品界面无需因此修改；原失败结果保留。

上述历史验收和首次安装失败分别归属于各自来源，此前的通过结论不覆盖后续运行时改动。修复后冻结来源的完整验收、对应 CI、源码对应关系、构建安装、七包 npm 读回及源码/npm/压缩包三路安装结果，以 GitHub Release 的证据资产为准。社区投稿与上游采用分别记录。
