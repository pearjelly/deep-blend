# 按实际表面放置模型

本轮从 0.18.0 的真实操作基线开始，目标是把“读取边界、计算高度、修改、再检查”收敛为一次有保存与预览的放置操作。当前仍是开发候选，未发布。

## 已观察的问题

在冻结的 0.18.0 提交 `a88a3307e8b617f06eed150abec7f31252209c36` 上，维护者通过正式 Host 导入同一个双网格 GLB。该资产含两个父级变换、原有 UV 和材质；主体另有旋转及非均匀缩放。

每个任务均执行 `getScene → 根据整体包围盒计算 Z 差 → applyScenePatch（保存和预览）→ getScene`，其中三个 Host 调用属于摆放任务，准备工程与入库另计。独立 Blender 重新打开前后文件，从全部实际顶点和预知支承面方程验证结果，没有使用候选放置算法。

| 支承 | 三次任务调用合计 | 包围盒上下边界差 | 实际最小竖直间距 |
|---|---:|---:|---:|
| 水平面 | 4.132 秒 | −0.000015 mm | −0.000012 mm |
| 斜面 `z = 0.2 + 0.2x` | 4.116 秒 | +0.000030 mm | **128.825039 mm** |

平面对齐成立，斜面仍悬空。原有局部几何、层级、UV、材质、旋转、缩放和 XY 均保持，旧修订全部文件字节保持。测量帧为 1，旧 Host 的默认预览帧为 24；独立检查证明这两个静态测试在两帧的全部几何和变换相同，原始记录没有改写帧号。

这是一组维护者操作基线，不是自然语言模型耗时、任意模型成功率或外部用户采用证据。原始基线脚本 SHA256 为 `a635c5bed57ceee1ee45e9c3a1895ef930c0956b2ad19b798adf96894fdc8b63`，独立读回脚本 SHA256 为 `52921c75dc96e536a7c024471d87a18b37e348fbdf8e7b00a70128650dbc1aeb`。

## 候选行为

`blender_place_on_surface` 选择已有主体、支承实体和明确帧，保留主体 XY、旋转、缩放，仅沿世界 Z 调整高度。支承可以倾斜；主体可以是生成网格或包含多个子网格的导入实例。`clearanceMm` 是 0–1000 mm 的竖直间距，默认零。一次成功操作保存一个可继续编辑的修订，并默认生成请求帧的预览。

对两个完整求值三角面集合，在所有共同 XY 位置求 `支承高度 − 主体高度` 的最大值，再加所需竖直间距。非退化三角形使用投影交集的顶点；竖直面、线或点投影以及数值不确定的情形使用精确有理数约束求解。孔洞和投影外的高边沿不会由整体包围盒代替。没有共同投影或超过完整计算预算时拒绝，不抽样后声称已接触。

Host 在同一个项目写入锁内绑定源修订、原生文件及全部资产，计算位置、隔离编译，再重新打开候选和基线。保存前比较全部实际顶点、拓扑与层级身份，确认主体只发生所请求的平移、支承不变，并复算残余偏差。允许的原生数值误差为 0.02 mm。预览使用同一明确帧；源变化、取消、编译、复验或预览失败均不发布候选。相同意图重试返回已保存结果。

第一版接受静态网格及独立修改器。动画、驱动、物理、外部对象几何依赖、隐藏或不完整层级，以及非米制原生单位需要明确拒绝。结论只覆盖所选两实体在该帧的求值网格；不证明物理稳定、欧氏最短间距、其他物体碰撞、移动路径、着色器位移或整段动画安全。

## 验收安排与当前发现

永久回归覆盖斜面、多部件导入、保持原状的旧修订、明确帧预览、重试，以及不可放置情形。独立原生读回用解析平面和完整顶点核对真实间距，不能用同一放置算法验证自身。下文另列已完成的真实 DSH 模型任务及相同案例前后比较，分开报告模型操作效率。

初次完整佛像只读探针载入 r0075 的 924,664,641 字节原生文件后，在 120 秒截止时间内未完成；原文件和隔离副本摘要保持。该失败保留，说明小模型通过不足以证明真实复杂资产可用。下一步以几何高度上界排除不可能影响结果的三角对，在保持完整性与明确预算的前提下复测同一案例。


同源候选复测已通过：两个起始 SceneSpec 与冻结基线逐字段相同，GLB 原始字节相同；flat/ramp 的单次 Host 放置分别为 4.163/4.275 秒。独立解析读回的竖直间距分别为 −0.000012 mm 和 0 mm，完整层级、UV、材质和旧修订文件保持。相较旧版的三次调用，收益为减少操作与修复斜面结果；本机底层总时间没有改善，不能写成渲染加速。候选预览使用请求帧 1，旧版默认 24 的静态差异沿用前述独立核对范围。首次复测因上传产生新的随机资产 ID 而未能通过逐字段起点检查，尚未执行放置；第二轮在正式资产声明中复用冻结的源 ID 后完成全流程，原失败记录保留。

完整佛像的严格高度上界剪枝后复测为 25.942 秒、正常退出：主体 35,643 顶点 / 64,000 三角面，支承 104 顶点 / 204 三角面，实际进入接触计算的候选对为 12。全部几何保留；跳过的面和树节点均有不能改善已确定可行接触值的高度上界。该次测得需上移 0.072837 mm，两个原生文件的 SHA256 均保持 `b415b65b765ed56c3bc45b7217e008b32bfadcec46e89b080df49d21489251aa`。这是原案例只读测量，不是修改该工程或完成新的成片。剪枝版本另通过 250 组完整网格的独立穷举有理数对照，无差异。


## 独立复核后的提交保护

只读审查用可重复的故障注入发现：若编译后、发布前把候选 `scene-spec.json` 的主体 X 从 0.1 改成 100.1，原生候选仍在正确位置，但旧提交路径会发布不一致的文档。候选现于最终发布点核对保存的规范 SceneSpec 字节及预计源码摘要；编译、原生复验和预览三个时点的文档改动均拒绝，当前修订及旧文件保持。

另一个探针让原生进程携带合法接触数据但以 139 退出，或返回错误动作/请求标识、缺失成功状态。新入口现要求正常退出、协议/动作/请求一致、明确成功且无错误，再接受几何证据；局部检查不改变其他原生动作的既有协议。直接 Host/SDK 的 `clearanceMm:null` 也与工具及原生端一致拒绝。

这些修正后的 Host 与 provider 定向检查共 54 项通过；正式 Blender 放置专项再次完成 26 项，覆盖解析平面、斜面、多部件导入、明确拒绝、同帧预览及旧来源保护。该读数仍不能代替完整验收或真实模型对照。初次完整契约运行的 143/146 保留为失败记录：三个问题是社区描述工具数、preset 技能漏列新工具，以及界面截图与当前客户端来源不同；运行期间审查脚本写入非忽略临时目录，也被冻结检查正确报告，故不作为稳定来源的通过证据。


## 真实模型对照与交付复验

同一中文请求、r0002 和初始图片的真实 DSH 对照使用 `bai/deepseek-v4.1-flash`、max/thinking，每次实际输出上限为 256000；完整历史保持；原始 PNG 原样保留，SDK 规范化后以完整 512×384 画幅输入，每臂一次完整回合，无自动重试。独立 Blender 读回确认三次运行均只有主体 Z 变化，实际竖直间距为零，原修订和资产保持。

| 运行 | 模型请求 | 全部工具调用 | 整轮耗时 | 原生与明确帧预览 | 通用文件卡片 |
|---|---:|---:|---:|---|---|
| 冻结旧版 0.18 | 11 | 15 | 171.503 秒 | 通过 | 成功 |
| 首次 0.19 候选 | 10 | 11 | 97.943 秒 | 通过 | 相对路径登记失败 |
| 修复后的 0.19 复验 | 10 | 13 | 165.206 秒 | 通过 | 绝对路径登记成功 |

旧版模型自行求解成功，不能把维护者包围盒基线的悬空结果当作旧版模型失败。首次候选虽保存正确，通用文件登记却因相对路径找不到文件而失败；该失败保留。回执补充当前项目绝对目录 `projectDirectory` 后，新的完整回合自然使用它登记 r0003 的 `.blend` 和 frame 1 预览，两个文件卡片均成功。最后一轮仍出现一次保存后不兼容几何查询的业务错误，模型修正查询后得到四条 `not-mesh`，没有把这些读数冒充接触证据。

三次实际运行共 31 个模型请求，完整请求、响应、会话与附件均保留核验，原始冻结代码、项目和个人部署字节保持。单例仅支持本例可完成与交付修复的观察；不据此推断普遍加速、成功率或降本。特别是首次候选的 97.943 秒伴随文件卡片失败，不能用它代表最终候选的完整交付耗时。


冻结后的首次完整入口另检出发布技能副本未同步：契约层 145/146，其中两条 preset 部署断言失败。该轮已保留并受控终止，受测源码未变；正式同步生成副本后，部署定向 9/9。上表 v6 的实际加载技能属于同步前版本，工具及运行时代码相同，不能把该次模型证据表述成最终随包技能输入的验证。
