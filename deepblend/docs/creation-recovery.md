# 创建失败后继续

从配方创建时，工作台保留点击时的名称、目标与参数。失败后的「重试上次创建」使用这份原输入；你后来输入的新草稿仍会保留。输入不变时再次点击创建也复用同一次请求，修改输入后直接创建则表示新的创作。

- Blender 不可用：界面给出环境检查指南，原输入留在当前页面。修复安装或路径后重试；更改 Blender 配置后先重启 `dsh web`，保留当前页面，让运行中的插件重新读取环境。
- 没有收到回执：项目可能已经保存。先用「刷新项目列表」检查；这是只读操作。原请求重试会恢复已创建项目，不另建项目或重复编译、渲染。
- 仍在处理：同一请求的并发写入被拒绝，稍后可再试。未完成的项目仍出现在列表中，但不能作为已完成项目打开，也不会自动选中临时的 `r0000`。
- 恢复成功：在实际落到的页面显示确认。已有项目的较新修改保持，恢复返回当前保存版本；原图片、作业和版本文件不因恢复而改写。

详细错误码和路径放在「详细诊断」。不要把没收到回执当成没创建成功，也不要在结果不明时反复另建项目。

## API 与模型工具

`blender_project_create` 和 Host `createProject` 支持可选 `creationKey`：1–128 个字符的非空文本，不含控制字符。首次创建选择一个新标识；相同输入的明确重试保留它，新项目使用新标识。标识不是权限凭据。

Host 把标识和创建输入的摘要记录在项目中，并在同一项目存储上协调写入。同一标识的不同输入被拒绝；成功记录在 Host 重启后仍可恢复，配方后来被移除也不会影响已有项目恢复。不提供标识的已有调用保留原行为，允许有意创建同名项目。

恢复能力由 `creationRequestProtocol: deepblend.creation-request/v1` 明确声明。工作台、HTTP 和模型工具在旧 Host 缺少该能力时拒绝依赖标识的创建；更新插件并重启 profile。恢复不根据名称猜测项目归属。

## 边界

工作台在当前页面中保留草稿和请求标识；应用内「刷新项目列表」不清除它们。重新加载页面或关闭标签页不承诺保留，可以从项目列表打开已经完成的项目。API/模型调用需要保留原 `creationKey` 和输入。

缺少已提交版本、重复标识或不一致的记录需要先检查；不会自动删除项目、修复记录或重新渲染。协调面向同一真实本地项目存储中的合作进程，不保护外部文件篡改或分布式文件系统。

本轮状态与实际验证见[每日记录](daily-releases.md)；候选验证不等同于公开发布。
