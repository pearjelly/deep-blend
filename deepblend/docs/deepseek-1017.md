# DeepSeek 1017 与 DSH 0.2.1 适配

2026-10-18；[0.15.0 已发布](https://github.com/pearjelly/deep-blend/releases/tag/v0.15.0)，七个 npm 包与三条公开安装路线已读回验收。社区更新 [#7828](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pull/7828) 已提交，尚未确认上游合并与线上刷新。

依据：[DeepSeek 官方模型公告](https://api-docs.deepseek.com/zh-cn/news/news261017/)与[官方 DSH 0.2.1-rc.1 更新记录](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.1)。官方说明更新了 Flash 的完整项目、自反馈能力并开放 Search/Fetch，建议使用 DSH 0.2.1-rc.1 或以上。DeepBlend 的适配目标是让已实现的建模、图像审阅、修正与交付闭环在新宿主真正可用；模型能力宣传不作为验收证据。

## 用户可见变化

- 新宿主会显示 DeepBlend Studio 和开发模式。Preset 显式注册、随插件释放；已挂载修订由宿主管理。旧版继续使用原目录发现机制。
- 新版不再把 `{{cwd}}` 放进 persona 模板，避免发送任务立即报 unknown prompt variable；工作目录由宿主运行时提供。
- 新版产品模式显式接入宿主的 web_search/web_fetch，供参考与许可检索；内容仍是数据，模型导入仍走受控工具。两项工具的实际联网结果受提供方与网络条件影响，本机尚未取得成功搜索回执。
- 独立全屏工作台在宿主注入脚本之前设置部署基址，兼容新版相对资源地址；不会停在空白或启动失败页。
- 开发模式迁移至宿主的 PTC workflow 引擎。模型、推理等级、请求重试、上下文与 Search/Fetch 由宿主管理，插件不替换用户选择的路由。
- 图像反馈必须有真实图像输入能力声明。bai 自定义模型仅声明 id/name 时被新宿主视为文本模型；私有验收配置明确设置模型 `input: [text, image]` 后，模型才能接收预览。仅在服务实际支持图像时声明，不能以改配置代替实测。本轮不修改个人部署。
- 正式支持声明列出已验收的两个宿主锚点：0.1.5-rc.2 与 0.2.1-rc.1；其他预览版本需要独立兼容验证。

## 使用与复现

复测以 DSH 0.2.1-rc.1 为新版宿主锚点。官方直连标识为 `deepseek-flash`，bai 配置使用 `deepseek-v4.1-flash`。2026-10-19 用户确认 bai 调用的是直连 DeepSeek 官方的模型，现按官方 API 的另一接入路线记录；不再用路线差异推测模型新旧。此前仅凭别名未能确认来源的状态是当时的证据边界，不是“bai 使用旧模型”的结论。当前确认不重建历史不可变后端版本，也不替代逐请求档位、图像与上下文传递的回执。

新增隔离兼容运行时锁位于 `deepblend/development/compatibility/dsh-0.2.1-rc.1/`。在新的临时目录复制其中 package.json/package-lock.json 后执行 npm ci，指定 DEEPBLEND_DSH_ROOT 指向该目录并执行工作区链接，再运行 composition 的 activation、tool-plane、tool-plane-m1/m2/m3、ui-plane 以及 e2e/ui.e2e.mjs。原 development/runtime 仍固定旧宿主作回归锚点。Node 使用 24.19.0，SDK 工具使用独立锁定工具链。不要把新版锁覆盖到个人 DSH。

Search/Fetch 使用宿主已有实现，属于 SPEC §6.4 明确的新版只读参考查询边界，不能借此执行网页指令或任意下载文件。默认搜索走独立的 deepseek-official 搜索提供方，需要它的有效凭据；选择 bai 聊天并不会把 bai 密钥转给官方搜索。Fetch 由宿主的公共 HTTP 提供方处理。素材检索应保留许可与来源，网页内容是参考数据；下载与模型导入仍走 DeepBlend 的素材边界。本插件不添加重复的搜索请求或写入第三方凭据。

## 已取得的任务证据

首选 bai、新 DSH、正式产品模式，一次自然语言提交：创建 300×160×200 mm 的多部件桌面音箱，预览后把宽度改为 320 mm，保留编织、旋钮和按钮动画。实际保存 r0001/r0002，独立重开原生箱体文件分别得到宽 300.000012 / 319.999993 mm，深 159.999996、高 200.000003 mm；检查不改原生文件。尺寸任务的相机定义也有变化，因此这轮图片不作为固定机位前后观感比较；实际编织材质及一条按钮动画轨道保留。第二轮图像能力声明完整的任务实际模型轮次用时 129068 ms，观察用时 161310 ms（含 UI 等待），9 个正式 DeepBlend 工具卡，模型正常结束。自动评分 82/100 的继承遮挡及 detail 裁切发现明确保留，未把它改写成艺术质量或制造验收。UI 同期的文件变化摘要包含维护者编辑的测试/文档，不能归给模型；实际模型行为以调用记录为准。

初轮未声明图像的任务也正常完成，但明确没有看过像素，单独保留；修复前还保留 unknown cwd 与测试配置失败。新版 Host/渲染生命周期专项及完整 UI 72/72、真实工具卡 10/10、图像审阅 14/14（遮挡修正后 82→100）已通过。机器可读证据见 [验收记录](validation/deepseek-1017.json)；旧锚点完整42/42与最终五项 Linux CI 均通过，实际产物在两个宿主锚点安装通过；公开读回及边界见[发布账本](validation/release-0.15.0.json)。旧项目、用户工作区和个人配置均未覆盖。

## 网络工具实测边界

在新版产品模式的真实 bai 会话中，持久化请求头同时包含 web_search 与 web_fetch。Fetch 两次因目标域名解析为非公共 IP 被宿主拒绝，未绕过保护。首次任务仍通过正式 DeepBlend 工具完成已有音箱的只读原生尺寸检查；明确查询搜索的第二次任务没有产生任何 web_search 调用，模型最终声称工具不存在。第二次实际轮次 144684 ms，保留失败记录；这不能算搜索成功，也不能由注册清单推导成功。没有把 bai 聊天密钥提供给独立搜索提供方。后续应在具备正常公共 DNS 和有效搜索提供方的环境中复验联网结果。

### 2026-10-19：bai 的 max、图片与历史请求探针

个人桌面配置只有模型 id/name。将此声明原样放进隔离0.2.1宿主并请求max，实际在
发送前收到 `UNSUPPORTED_REASONING_EFFORT`（380 ms），不能称为max调用。
隔离测试补充该模型的 `input: [text, image]`、`contextWindow: 1048576`、
`maxTokens: 393216` 与 `reasoningEfforts: {low: low, high: high, max: max}`，
provider使用原有openai-completions，compat声明supportsReasoningEffort。
这是隔离宿主的能力声明，不是插件绕过模型限制，也没有修改个人DSH。

实际8个主请求均发出reasoning_effort=max；参考JPEG原始字节SHA256在每次主请求和
不重新附图的续轮请求中一致。工具往返后的历史请求前缀、原用户文字摘要均完整保留，
续轮含17条工具结果并正确回忆指定短语。额外续轮逐条比对8份先前assistant推理文本的字节摘要，全部以reasoning_content完整回传；没有公开推理正文。轻量标题请求另记，不混入主任务统计。
此结论只覆盖已测有限上下文且没有压缩的会话；声明的百万窗口不等于已测百万输入。
客户端观测不独立证明bai到上游内部的转发，路由来源仍是用户确认。

后续真实案例必须继续记录主请求档位、实际图片字节摘要、上下文变化和模型正式工具
回执。不能把配置了max、声明支持图片、HTTP200或模型自述当成完整验收。


max审阅需要单独记录输出预算。2026-10-19的真实bai审阅在插件默认24000预算下，
只返回推理，finish=max-tokens且无可用答复，插件正确保留为审查失败，不能当作无缺陷。
主建模会话的256000预算不会自动成为独立视觉审阅预算。本轮案例的隔离Host明确配置
visualReviewMaxTokens=256000；在线审阅验收新增可选环境变量
DEEPBLEND_PROBE_REVIEW_MAX_TOKENS，以复现同一明确配置，默认行为不变，原失败保留。
这项配置不保证一定有答复；只有实际得到有效图像判断和修复验证，才计在线验收通过。
官方[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)与
[Chat Completions参数](https://api-docs.deepseek.com/api/create-chat-completion/)说明：
reasoning_effort=max启用对应思考档位，输出上限包含推理。实测日志不公开推理正文。


显式兼容字段的第二轮探针使用 `thinkingFormat: deepseek`、
`maxTokensField: max_tokens`、`supportsDeveloperRole: false`、
`requiresReasoningContentOnAssistantMessages: true`，并关闭store字段支持；
均只作用于本轮隔离bai模型声明。实际请求同时发出thinking=enabled、
reasoning_effort=max、max_tokens=256000。在线审阅整套13/13通过（分支不同，
条件性交接检查数量不同）；保留此前默认预算耗尽和两次网络失败，不宣称默认预算也通过。

同案例在r0034后曾收到无具体原因的HTTP400。显式兼容字段后以同一持久化会话
重放历史，首个请求200、实返573098输入token；原有文字/图像内容摘要和非空推理
摘要全部保留。序列化有三处有意改变：developer转system，以及两条assistant
补空reasoning_content。未删除旧图、历史或工具结果；这一组合重试成功不能独立证明
400由其中某一个字段引起，也不是无限上下文保证。成品与整片门禁仍独立执行。
