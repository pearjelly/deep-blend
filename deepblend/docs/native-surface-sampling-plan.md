# 原生局部表面采样：2026-10-14 探针与下一切片

0.9.0 的实际部件跨度不能回答壁厚和内衬间隙。先对已验收的四份保存模型做只读探针，
再决定可接入的协议。这里没有发布新产品能力，也没有重新调用 bai 或新增成品认可。

## 实测

`9566f591992aa55f8ea4d57f27b511c9f15a1879`；Blender 5.2.1 LTS。

## 可报告范围与拒绝条件

对第一处迎向射线的表面，沿其实际三角面法线向内寻找第一处向外的表面，报告两个
命中点之间的弦长；如指定另一个实体，从出口沿同一法线寻找它的第一处迎向表面。
后者只描述指定两实体的沿射线距离，还要拒绝先遇到源物体另一表面的遮挡。
未检查其它场景物体是否介入，不能把这个距离叫作全装配净间隙。

只接受闭合、单连通分量、边方向连续、正有向体积的实际求值网格。拓扑门槛不证明
没有自相交。普通实体可有缩放和旋转，但反射导致反向绕序的网格先拒绝；不替用户
自动修正。每例最多8实体、8射线；每实体最多250,000顶点和250,000面。
种子搜索上限0.5 m，向内和目标搜索上限各0.1 m，偏移epsilon为0.0001 mm。

九个解析/反例场景通过十条断言：已知2 mm实体和2 mm间隔、斜种子、平移旋转、
种子在实体内、射线未命中、目标重叠、源物体遮挡目标、反向绕序、开放表面。
不适用的查询输出具体状态，不输出假零或从包围盒推导数字。
错误checkpoint摘要、零方向、超量选择三项输入反例均以进程1退出，未生成可接受的
测量报告；源文件未修改。

这些是固定点局部采样；不能证明全表面最小壁厚、最小距离、无碰撞、加工安全或成品
质量。三角面法线也不等于着色法线。早期粗面数圆环的法线射线绕过对侧实体，导致
遮挡反例假设失败；提高面数后才构成真实遮挡。原始失败日志保留，不能忽略这一风险。
首次旋转探针把局部种子再次缩放到实体内也失败；改为正确世界种子后整轮重跑。

## 接入计划与发布门槛

1. 扩展现有场景检查入口的可选有限射线选择，默认0.9.0输出保持。请求写明源实体、
   可选目标实体、世界种子、方向、搜索距离、帧；不会让模型提交任意Python或对象路径。
2. 复用当前保存版本、原生生产者SHA、私有副本、资产核对、取消和旧回执拒绝机制。
   新报告严格验证请求身份、状态、所有命中点/单位法线/距离与有限预算。
3. 回执把采样条件、失败原因、局部证据和未证明条件一起返回。工作台显示同一保存版本
   的可检查采样；编辑草稿、过期结果和被修改原生文件不得混入保存版本读数。
4. 实际杯/灯/音箱建立支持与不支持基线，包括旋转缩放、未命中、重叠、遮挡、手工修改、
   取消、来源变化和预算；反例必须保证没有错误的正向结论。
5. 以 bai 复测保存项目修改任务，看模型能否引用前后真实局部采样，并准确保留未测条件。
   记录一次任务的操作数、工具数、完成时间、返工和固定条件前后图。
6. 完整冻结验收、公开CI和标准发布全部通过后才发布下一稳定版。本次没有升版本。

接续文件路径已核对：共享契约为`packages/deepblend/contracts/lib/geometry-inspection.js`，
原生实现为`packages/deepblend/provider-local/python/deepblend_inspect_geometry.py`，
Provider的`inspectGeometry`须显式转发新增选择；Host为
`packages/deepblend/host/lib/geometry-inspection.js`，模型入口为工具包的现有
`blender_scene_get`。当前两级报告和工具验证都是严格v1，不能偷偷附加未验证字段。
新增采样应使用明确的协议版本/能力识别；普通读数继续保持v1，旧Host/Provider给出
升级提示。工作台再接同一契约，避免单独计算一份距离。

诊断脚本为 `deepblend/tests/lib/inspect-native-surface-samples.py`。输入格式见脚本开头；
从原生验收产物复制输入文件，固定每份文件的SHA256，按原始数据中的实体/帧/射线构造
配置，用 `--python-exit-code 1` 执行。Blender默认可能在Python断言失败后仍返回0，因此
除进程结果外，还必须检查报告存在、全部预期案例和源文件摘要。
